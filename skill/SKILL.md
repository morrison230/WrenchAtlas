# WrenchAtlas · 汽车电路诊断

## 这是个平台，不是单车型工具

数据组织成**车型包**，一款车一个目录。加新车不改代码，只加数据包。

```bash
# 第一步永远是这条：看装了哪些车
PY=python          # 确保 python 在 PATH；不在则写绝对路径
"$PY" "$Q" --list-packs
```

**回答前必须先确认车型对得上**。用户问"卡罗拉打不着火"，而数据包里只有 SX4，正确回答是：

> 目前只装了铃木 SX4 的数据，没有卡罗拉。可以加，但需要你提供该车合法持有的手册。

而不是拿 SX4 的起动回路去套。

## 当前已装的车型

| pack id | 车型 | 数据量 |
|---|---|---|
| `suzuki-sx4-2010` | 长安铃木 SX4 2010 · M18A（1.8L） | **36 系统 / 1537 页全文** |

**具体有哪些系统、哪些症状，一律用 `--list` 现查，不要照抄本文档。** 数据会一直加，静态列表必然过期。

```bash
"$PY" "$Q" --list          # 当前车型的全部系统
"$PY" "$Q" --list-packs    # 所有车型
```

## 三层数据，能力不同

| 层 | 覆盖 | 能回答什么 | 局限 |
|---|---|---|---|
| **结构化拓扑** | 36 个系统 | 诊断树、针脚、排查步骤 | 只有已录入的系统 |
| **全文 OCR** | 1537 页 | 「这个词在第几页」 | 搜得到 ≠ 读得懂，数字尤其不可靠 |
| **原图渲染** | 按需 | 点开看真页 | 首次渲染 3~4 秒 |

**关键限制：全文搜不到数字。** `0.15`、`45N·m` 这类基本搜不到（OCR 把小数点识别丢了）。
查规格只能：搜术语 → 定位页 → 打开原页 → 人眼读。**绝不要从 OCR 文本里读规格值报给用户。**

**连接器号特别好用**：`E323`、`G144` 这类编号在电路图上是独立大字，识别准。
搜它一次能同时拿到「哪个系统用它 + 原图哪页 + 连接器布置图里在车上哪个位置」。

## SX4 这台的资料状况（重要）

- **电路图**：2010 长安版，114 页彩色线路图，已全部增强，图上标注 M16A/M18A 均适用

## 怎么查

**永远先查数据，不要凭记忆回答。** 跨年款、跨厂牌差异大，凭印象答等于编。

```bash
PY=python          # 确保 python 在 PATH；不在则写绝对路径
Q="$HOME/.workbuddy/skills/wrench-atlas/scripts/query.py"

# ① 症状问诊（最常用）—— 用户说人话，这里按第一刀分流
"$PY" "$Q" "打不着火"
"$PY" "$Q" "冷车抖"
"$PY" "$Q" "空调不制冷"

# ② 故障码（直接映射到缸号/连接器/ECM 引脚）
"$PY" "$Q" "P0301"

# ③ 连接器号 —— 会连带查出它还出现在哪些系统
"$PY" "$Q" "G144"

# ④ 列出全部系统与症状
"$PY" "$Q" --list

# ⑤ 精确查看某个系统 / 某个症状
"$PY" "$Q" --system ignition
"$PY" "$Q" --symptom no-crank

# ⑥ 生成诊断报告（用户说"导出一份""打印出来""我要带去车边"时用）
"$PY" "$Q" --report ignition                    # 单系统，直接打印在对话里
"$PY" "$Q" --report all -o D:/报告.txt           # 全量，写入文件

# ⑦ 多车型：指定车型包
"$PY" "$Q" --list-packs                          # 看装了哪些车
"$PY" "$Q" --pack toyota-corolla-2014 "打不着火"   # 查指定车型
"$PY" "$Q" --pack toyota-corolla-2014 --list      # 看该车型录了哪些系统

# ⑧ 手册全文（1537 页 OCR 索引）
"$PY" "$Q" --fulltext "制动警告灯"                 # 只搜全文，返回页码与片段
"$PY" "$Q" "制动警告灯"                            # 普通查询会自动附带全文命中
"$PY" "$Q" --no-fulltext "起动"                    # 只要结构化结果，不要全文
```

**报告什么时候主动给**：用户明确说要打印、要带去车边、要存下来，或者问的是安全相关部件（制动/气囊/转向）需要逐条核对时。日常问答不用生成，直接回答更快。

**报告里已经自带的东西**：来源页码、置信度、存疑项单列、跨系统牵连、勾选框、免责声明。回答用户时不要重复堆一遍，指出文件位置即可。

数据包路径变了就加 `--pack <路径>`，或设环境变量 `WRENCHATLAS_PACK`。

## 症状层是入口，别跳过

用户描述通常是症状（"打不着""抖""灯不亮"），不是系统名。**先按症状查**，里面已经写好了「第一刀往哪切」，直接照着问就行。

症状共 12 类，每类只问一个能把故障范围砍一半的问题：

| 症状 | 先问这一句 |
|---|---|
| 打不着火 | 拧钥匙能听到『哒』一声吗？ |
| 起动机转但不着 | 转速表指针动不动？ |
| 怠速抖 / 失火 | 报的是哪个缸？ |
| 不充电 | 电瓶灯是常亮，还是不亮也不充？ |
| 大灯不亮 | 左右都不亮，还是只有一侧？ |
| 转向灯不亮 | 双闪正常吗？ |
| 喇叭不响 | 双闪正常吗？ |
| 空调不制冷 | 出风口有风吗？ |
| 鼓风机不出风 | 只有最高档有风，还是全没风？ |
| 雨刮不动 | 喷水还工作吗？ |

**用户答不上来时，把这句问题原样问他**，比自己猜快得多。

## 回答的铁律

1. **必须带溯源**：每个结论后面跟「见 XX 系统 p1」这样的页码。没页码的结论等于没依据。
2. **必须标置信度**：数据全部是人工从扫描图判读的，**没有一条经过实车核对**。涉及"量哪个针脚""这个值是多少"时，说明"这是从电路图读出来的，以实车实测为准"。
3. **存疑项要点名**：数据里标了 `read-uncertain` 的地方（如起动系统的 ECM 搭铁控制、充电系统的 C312 压接点），回答时要主动说明"这里原图不够清晰/接法待确认"。
4. **欧4 / 非欧4 陷阱**：点火系统的 ECM 控制引脚有两套——非欧4 是 C01 6/5，欧4 是 C01 53/40。**在用户确认排放标准之前，不要给单一定论。**
5. **安全气囊、制动、转向**相关的问题，必须加一句"以原厂手册和专业判断为准"。
6. **不给推算值**。扭矩、间隙、电压只报手册原文，不做换算。

## 最值钱的几条结论（可直接用，但记得带页码）

- **发动机完全打不着 + 转速表不动** → 首查 CKP（C31.2 粉红线 → ECM C01 21），这是最高优先级，比查油查火都快
- **1&4 缸同时失火** → 判定 C101 点火线圈坏（废火花系统，线圈坏必成对）；**2&3 缸同时** → C102
- **只有单缸失火** → 优先火花塞，线圈可能性低
- **拧钥匙没『哒』声** → 控制回路断（JB ST SIG 10A / 点火开关 ST / 继电器线圈）；**有『哒』不转** → 主回路（触点/电磁开关/30A/大电流线）
- **雨刮和喷水全不动** → 先看 JB 30A WIP 保险丝，两者共用
- **雨刮停不到位、反复摆** → 回位回路 E64.1 蓝白线 + G334 搭铁
- **动作慢、无力** → 优先怀疑 G334 搭铁不良，不是电机坏
- **AT 车型 D/R 档拧钥匙没反应是正常的**，只有 P/N 档能起动
- **换新电瓶很快没电** → 充电系统正常的话，查漏电，不属充电系统
- **喇叭不响 + 双闪也不闪** → HORN-HAZ 保险丝同时供两者，一步定位
- **转向灯闪得明显变快** → 有一个转向灯泡烧了（闪速由负载电流决定），换灯泡即可
- **单侧大灯不亮** → 左右各有独立保险丝（HL L / HL R）与独立继电器，先查该侧保险丝
- **刹车灯不亮但刹车正常** → 先看 STOP 15A，再看踏板开关 E181 是否顶不到位
- **空调不制冷先分两件事**：出风口有风吗？有风→制冷侧（A/C 20A、E229、C141、ECM 否决、制冷剂）；没风→鼓风机（转 heater 系统）
- **鼓风机只有最高档有风** → 风机电阻烧断。原理：G65 的 1 号抽头（黑/白）直通不经过电阻，所以电阻全烧了最高档照样转。换电阻，不用换电机

## 页面图怎么看

`pages/` 下是 300dpi 增强图，文件名格式 `06-系统电路图__<系统名>__p001.png`。

要看具体某一页，直接读图即可（不需要 OCR）。原图很清晰，连接器编号、针脚号、线色都能辨认。

网站也能看：`start.bat` 启动后 `http://127.0.0.1:3000`（手机同 WiFi 用内网 IP）。
