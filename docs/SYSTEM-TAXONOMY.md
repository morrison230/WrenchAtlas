# 系统标识词表（跨车型标准）

> 版本 v0.1 · 2026-10-25
>
> **这份表是平台的地基。** 不同厂牌的手册标题千差万别（丰田叫"充电系"、本田叫"充电系统"、大众叫"发电机"），
> 但诊断逻辑是相通的。统一标识以后，才能做到：
>
> - 加一款车只填数据，不改代码
> - 跨车型对照（"这车起动回路和那车差在哪"）
> - 症状问诊树跨车型复用

## 命名规则

1. 全小写，单词用连字符：`wiper-front`，不写 `wiperFront` 或 `WIPER_FRONT`
2. **用功能命名，不用零件命名**：`charging`（充电），不是 `alternator`（发电机）
3. 位置/侧别作后缀：`wiper-front` / `wiper-rear`，`fog-lamp-front` / `fog-lamp-rear`
4. 一个系统一个标识，**不许为了省事合并**（"灯光"塞一个 `lighting` 会让诊断树混乱）

## 新增标识的规则

通用表里没有对应项时（比如某车有"四驱耦合器控制"），允许自创，但必须：

1. 符合命名规则（小写 + 连字符 + 功能命名）
2. **登记到本表**，并注明首次出现的车型包
3. 在车型包的 `README.md` 里说明这个系统包含什么

自创标识不加进本表，就等于只有你知道它是什么意思 —— 平台化就断了。

## 自查

跑这条命令，会列出数据包里所有用到的 system 标识：

```bash
cd <项目根目录>
python -c "
import json
from pathlib import Path
for pack in sorted(Path('packs').iterdir()):
    d = pack / 'data' / 'circuits'
    if not d.exists(): continue
    sysids = set()
    for f in d.glob('*.json'):
        sysids.add(json.loads(f.read_text('utf-8'))['system'])
    print(pack.name, '->', ', '.join(sorted(sysids)))
"
```

对照本表检查：有没有拼写变体（`wiper_front` / `frontwiper`）、有没有该合并却拆开的、有没有表里没有的新标识。
