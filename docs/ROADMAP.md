### 为什么实际比计划多走了两步

计划里「多车型」只是 M6 的一个子项，「全文检索」根本没提。做到一半发现两件事：

1. **用户要的不是"我的车能用"，是平台** —— 于是把系统词表、包结构、服务层全部重构成车型无关（M4.5）
2. **"在线手册查询系统"必须能搜整本手册** —— 于是补了 OCR 全量管道（M4.6）

这两步都不在原计划里，但它们改变了项目性质：**从"一个 SX4 工具"变成"一个可扩车型的手册平台"**。

### 为什么 M5 动画被搁置

- 正确的电流方向需要精确拓扑 + 开关逻辑 + 继电器时序，**只能逐条手工建模**
- **做错的动画比不做更害人**（照着错的电流方向查，会把好件换掉）
- 而流图 + 诊断提示已经解决了"该查哪一环"这个真需求

**结论**：锦上添花，不是刚需。留着，但不占优先级。

## M1 · 单条回路打通（最关键的一步）

**为什么从雨刮开始**：我实测看过这张图——`10-挡风玻璃雨刮器和清洗器.pdf` 第 1 页，元件最少（蓄电池→保险丝→点火开关→电机→搭铁），连接器编号清晰（E323 / E64 / G334 / G271）。**用最复杂的图验证架构是自找麻烦，用最简单的图验证才看得清哪里没打通。**

**要做的事**
1. 该页高清渲染 + 裁切
2. 手工录入这条回路的完整拓扑（这一次**故意手工**，不写自动化）
3. 网站能显示：原图 + 可点击针脚热区 + 点一下高亮整条回路
4. 每个节点旁显示「原页第几页」可跳转

**验收标准（你会亲手试）**
- [ ] 双击 `start.bat`，浏览器自动打开，看到雨刮线路图原图
- [ ] 点击 `E64.3`，从它到 `E323.9` 的整条路径高亮
- [ ] 点「看原文」跳回 PDF 对应页
- [ ] 故意点一个没录入的针脚，界面明确说"未收录"，而不是假装没有
- [ ] **手机连同一个 WiFi，扫码打开，能双指缩放、能点针脚追线**

**手机必须在 M1 就验，不能留到后面补**：原图 4560 像素宽，手机上的交互逻辑（总览/放大两态、触控热区）跟桌面完全不同，晚做等于重做。

**为什么值得慢**：这一步会暴露数据模型的所有问题。手工录入 20 个节点就能发现字段设计错在哪，比写完 2000 行自动化代码再发现要省太多。

## M2 · 数据管道半自动化

**目标**：把 M1 的手工活变成"机器出草稿 + 你校验"。

**要做的事**
1. 分色模块（已验证可行：五色全分离）
2. 走线骨架化 + 直角化 + 断口检测（标注"这里断了，需人工连"）
3. 连接器编号 OCR + 位置绑定
4. 生成草稿 JSON，标记 `verified: false`
5. 网站加"校验模式"：逐条确认/修正，确认后转 `verified: true`

**验收**：拿一张没见过的图，机器出草稿，你 5 分钟内校验完，结果与原图一致。

**风险**：交叉点和断口判定。这是全项目技术难度最高的地方，可能只能做到"80% 自动 + 20% 人工"，那不丢人——**只要人工那一关有工具支撑**。

## M3 · 首批三个系统（拆成三小步）

你选的是**发动机控制 · 起动充电 · 车身电器**。但我建议**按"易 → 难"反着推**，不按前两个先做：

| 步骤 | 系统 | 为什么这个顺序 |
|---|---|---|
| **M3a** | 车身电器 | 接 M1 的雨刮继续，元件少、DTC 少，先把格式和工具链压顺 |
| **M3b** | 起动充电 | 回路简单但极高频（打不着火第一嫌疑），性价比最高 |
| **M3c** | 发动机控制 | DTC 表最厚、诊断树最深。放最后，用成熟工具链啃硬骨头 |

如果你急着先要发动机控制（毕竟抖/难着/油耗最烦），也能换到前面，代价是边摸索格式边处理最复杂的数据，返工率高。

**每步的验收**：说一句真实症状 → 给出分步排查 → 每步能跳原文。

**M3 全程必须过的关**：所有规格条目带 `engine_mismatch` 标记，M16A 来源的数值一律标红提示。

## M4 · Skill 接通 ✅

**目标**：对话里直接问诊。

**已完成**
1. `skill/SKILL.md` 定义问诊工作流与回答铁律
2. `skill/scripts/query.py` 检索脚本：关键词 / 系统 / 故障码 → 命中条目
3. 已安装到 `~/.workbuddy/skills/wrench-atlas/`
4. 每条结果自动带来源页与置信度

**实测**
- `--list` 列出 5 个系统及各自环节/连接/提示数量
- `P0301` → 命中「缸1 · C91 · C01 1」故障码映射
- `起动机` → 命中起动系统 6 条诊断提示
- `失火` → 命中点火系统，并自动带出欧4/非欧4 警告

**验收**：在 WorkBuddy 里说"1.8 天语冷车抖"，能定位到系统、给排查步骤、标页码。（需新会话加载 skill 后验证）

## M5 · 动画回路

**目标**：3–5 条高频回路做成正确的电流动画。

**前提**：拓扑必须 `verified: true`，否则不做动画。**错的动画比不动更有害。**

**候选**：起动回路、燃油泵回路、点火回路、雨刮回路、大灯回路。

## M6 · 开源化

**目标**：别人 clone 下来，拿自己的手册能跑出包。

**要做的事**
1. `DATA-FORMAT.md` 写成规范（别人照着能产包）
2. builder 加 CLI 引导
3. 模板包 `packs/_template`
4. README 写清免责与版权边界
5. 检查仓库里无任何原图残留（这一步要写脚本自动查）

**验收**：仓库公开后，不含任何原厂图，且文档能让陌生人跑通。
