# WrenchAtlas · 扳手图志

把**原厂维修手册的扫描件**变成可检索、可点选、可推理的车型知识图谱。

一份数据，两个前端：

- **网站**——给人看：原图打底，点连接器追整条回路，按症状查诊断树
- **Skill**——给 AI 用：对话里问诊，每一步都标回手册页码

**这是一个多车型平台，第一款车只是样本。** 架构上车型 = 一个数据包目录，加新车不改代码：

```
packs/
├── _template/            模板（不参与运行时）
├── suzuki-sx4-2010/      ← 第一个数据包（已建成）
├── toyota-corolla-2014/  ← 第二个只需要这样新建
└── ...
```

建新车型：

```bash
python builder/new_pack.py --id brand-model-year --make Brand --model Model --year 2020 --engine XXX
```

然后按 [`docs/MULTI-VEHICLE.md`](docs/MULTI-VEHICLE.md) 走八步。服务启动时自动扫描全部车型包，网页顶部出现车型切换器。

**为什么能扩**：系统标识用跨车型标准词表（[`docs/SYSTEM-TAXONOMY.md`](docs/SYSTEM-TAXONOMY.md)），拓扑按 `role` 自动排版（不存坐标），所有接口接受 `?pack=<id>`。

---

## 它解决什么问题

修车时最费时间的不是动手，是**找信息**：

- 手册 1600 多页扫描件，全无文字层，Ctrl+F 搜不到一个字
- 电路图是书摊开拍的，跨页、书脊弯曲，一条线要来回翻三页才对得上
- 症状表、故障码、扭矩值分散在不同章节，凭记忆翻

WrenchAtlas 把这些变成：输入"雨刮不动"，直接给分步排查 + 每一步该看哪一页。

## 快速开始

```
双击 start.bat
```

浏览器自动打开 `http://127.0.0.1:3000`，控制台会打印手机访问地址（同一 WiFi）。
只有一个车型包时不显示切换器；多个包时顶部出现下拉。

首次使用需要先生成页面数据（只需一次）：

```bash
python builder/enhance.py --src <手册目录> --out packs/<车型id>/pages
python builder/index.py   --pack packs/<车型id> --doc-id <doc_id>
```

依赖：`pymupdf opencv-python-headless fastapi uvicorn pillow numpy`

## 现在能做什么

五个入口 + 报告导出，按「你手上有什么」分流：

| 入口 | 地址 | 什么时候用 |
|---|---|---|
| **手册浏览** | `/` | 要看原厂图。114 页增强版，点线路自动高亮整段 |
| **诊断流图** | `/flow` | 大概知道哪个系统，要看拓扑。23 个系统，点环节看针脚，一键跳原图 |
| **症状问诊** | `/symptom` | 知道车怎么了、不知道是哪。12 类症状，每类先问一句把范围一分为二 |
| **全站搜索** | `/search` | 手上有个编号/故障码/一句话。连接器、故障码、症状、提示、手册页一次搜完 |
| **实车核对清单** | `/checklist` | 要逐项量。177 个环节按「存疑 → 跨系统关键件 → 常规」排序，勾了就变绿 |
| **诊断报告** | `/report?sys=<系统>` | 要打印带去车边。A4 打印页，勾选框留白，存疑项单列 |

### 全文检索：给 1638 页扫描件装上 Ctrl+F

手册是纯扫描件，一个字的文字层都没有。已用 **Windows 内置 OCR**（系统自带简体中文）建全文索引：

```bash
python builder/ocr.py --src <手册目录> --pack packs/<车型> --doc-id <doc_id>
python builder/ocr_sources.py --src <手册目录> --pack packs/<车型> --doc-id <doc_id>
```

建完后搜索框就能搜整本手册，**结果点一下直接打开原页**（`/api/manualpage` 按需渲染 + 磁盘缓存）。

实测：200–750ms/页；检索 15–130ms；原页首次 3.7s、缓存后 9ms。

**边界（重要）**：OCR 文本**只用于定位页码，绝不用作数据来源**。
密集小字页错字率高（`通风良好` 会变成 `通风蚜`），扭矩/间隙这类数字必须看原页核对。
详见 [`docs/FULLTEXT-OCR.md`](docs/FULLTEXT-OCR.md)。

纯文本报告也能直接从对话里要：`query.py --report ignition`（单系统）或 `--report all -o 文件.txt`（全量，约 3000 行）。

流图的意义：原厂接线图回答"这根线接哪个针脚"，流图回答"哪一环断了"。诊断时要的是后者。

报告的意义：手机翻页不方便，纸上勾选才跟得上手。所以报告里每个环节、每条排查步骤前面都是空格子。

## 设计要点

| 要点 | 做法 |
|---|---|
| 多车型 | 引擎与车型数据彻底分离，代码里没有车型字面量 |
| 电路图 | **不重绘**。原厂图作底，矢量交互层叠加——原图才是权威 |
| 动画 | 只对已校验拓扑的回路做。没有正确拓扑的动画会误导排查 |
| AI 可信 | 每条结论强制带页码溯源，未校验数据显式标红 |
| 开源友好 | 只开源引擎与工具链，车型数据由使用者用自己的手册生成 |

详见 [`docs/DESIGN.md`](docs/DESIGN.md)。

## 版权与免责

本项目**不分发任何原厂维修手册内容**。

- 手册 PDF、渲染页面图片均在 `.gitignore` 中，永不进入仓库
- 仓库内仅包含：引擎代码、数据格式规范、以及从手册中提取的结构化事实（连接器编号、回路拓扑、诊断步骤编号）
- 使用者需自行合法持有对应车型的维修手册，并用 `builder` 在本地生成自己的数据包

**免责**：本工具仅辅助定位维修信息，不能替代原厂手册与专业判断。涉及安全气囊、制动、转向系统的操作，务必以原厂手册为准。因误用造成的任何损失，作者不承担责任。
